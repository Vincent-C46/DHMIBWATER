## 1. 배경

SHP/DXF 각 레코드 = 폴리선 1개. 폴리선 끝점이 다른 폴리선 위에 있으면 T분기, 서로 교차하면 십자이며
그 절점에 이형관이 들어간다. 폴리선이 꺾이는 절점에는 곡관이 들어가는데, **표준 곡관 각도
{11.25, 22.5, 45, 90}° 각각이 직경별 허용굴곡 ±δ 를 가지므로 그 범위 안에 들어올 때만** 곡관을 넣는다.

## 3. 신규 1 — `Core/Gis/BendToleranceTable.cs`

```csharp
namespace DHBIMWATER.Core.Gis;

/// <summary>관종·직경 조합의 허용굴곡(도). DiameterMm은 "이 직경 이하"를 포괄하는 구간 상한이다.</summary>
public sealed record BendToleranceEntry(string PipeKind, double DiameterMm, double ToleranceDeg);

public sealed class BendToleranceTable
{
    /// <summary>표준 곡관 각도(도). 이 목록 자체는 사용자 설정 대상이 아니다.</summary>
    public static readonly IReadOnlyList<double> StandardAngles = new[] { 11.25, 22.5, 45d, 90d };

    public BendToleranceTable(IReadOnlyList<BendToleranceEntry> entries);
    public IReadOnlyList<BendToleranceEntry> Entries { get; }

    /// <summary>
    /// 관종·직경에 해당하는 허용굴곡(도). 조회 규칙:
    /// (1) 관종이 같은 항목 중 DiameterMm이 입력 직경 이상인 것 가운데 가장 작은 직경의 값,
    /// (2) 그런 항목이 없으면 같은 관종의 최대 직경 항목 값,
    /// (3) 관종이 하나도 없으면 관종 무관 전체에 같은 규칙 적용,
    /// (4) Entries가 비어 있으면 0을 반환한다(=곡관을 하나도 못 넣고 전부 Unresolved가 되어 설정 누락이 드러난다).
    /// </summary>
    public double ToleranceFor(string pipeKind, double diameterMm);

    /// <summary>설정 미저장 상태에서 UI가 초기값으로 제시하는 임시 표.</summary>
    public static BendToleranceTable Default { get; }
}
```

## 4. 신규 2 — `Core/Gis/BendResolver.cs` + `NodeClassification.PipeKind`

### 4-1. `PipeNetworkClassifier` 수정

`NodeClassification`에 `string PipeKind`를 **`MinDiameterMm` 뒤에** 추가한다(위치를 지키면 기존 positional 생성 순서 혼동이 없다).
값은 **접속 간선 중 최대 직경 간선의 관종**(동률이면 먼저 등장한 간선). 접속 간선이 없으면 `string.Empty`.
이유: 이경티/레듀서에서 허용굴곡은 주관 기준으로 보는 것이 보수적이다.

`PipeNetworkBuilderTests`가 `NodeClassification`을 positional로 생성하지 않으므로 기존 테스트는 영향받지 않는다. 확인할 것.

### 4-2. `BendResolver`

```csharp
public enum BendResolutionKind
{
    /// <summary>편각이 허용굴곡 안 — 곡관 없이 직관 편차로 흡수한다.</summary>
    None,
    /// <summary>표준 곡관 1개로 해결된다.</summary>
    Standard,
    /// <summary>어느 표준각의 허용범위에도 들지 않는다. 곡관을 넣지 않고 사용자 확인 대상으로 남긴다.</summary>
    Unresolved
}

/// <param name="StandardAngleDeg">Standard면 선정된 표준각, Unresolved면 가장 가까운 표준각, None이면 0.</param>
/// <param name="ResidualDeg">편각과 StandardAngleDeg의 차(부호 포함). None이면 편각 그대로.</param>
public sealed record BendResolution(
    int NodeId, BendResolutionKind Kind, double DeflectionDeg,
    double StandardAngleDeg, double ToleranceDeg, double ResidualDeg);

public static class BendResolver
{
    public static BendResolution Resolve(NodeClassification node, BendToleranceTable table);
    public static IReadOnlyList<BendResolution> ResolveAll(IReadOnlyList<NodeClassification> nodes, BendToleranceTable table);
}
```

판정 순서 (`Resolve`):

1. `node.Kind`가 `Bend`가 아니면 `Resolve` 호출 대상이 아니다 → `ArgumentException`.
   `ResolveAll`은 `Kind == NodeKind.Bend`인 절점만 골라 처리한다.
2. `δ = table.ToleranceFor(node.PipeKind, node.MaxDiameterMm)`.
3. `θ ≤ δ` → `None`.
4. `|θ − a| ≤ δ`인 표준각 a 중 `|θ − a|`가 최소인 것 → `Standard`.
5. 그 외 → `Unresolved`. `StandardAngleDeg`에는 `|θ − a|`가 최소인 a를 담는다.

**중요** — 4번에서 여러 표준각이 걸리면 가장 가까운 것을 고른다. 동률(정확히 중간)이면 **작은 각**을 고른다.

> ### 표준각 범위 밖 편각은 이번에 풀지 않는다
> 예: θ=16°, δ=5° → 11.25°와도 22.5°와도 안 맞는다. 곡관 조합(11.25°×2 + 짧은 직관 등)이나
> 특수 곡관으로 처리해야 하지만, **조합 시 최소 직관 길이·중심선 이탈 허용치·우선순위(부재 수 최소 vs 오차 최소)가
> 아직 정해지지 않았다.** 이번 구현은 `Unresolved`로 표시만 하고 곡관을 넣지 않는다.
> `BendResolver`에 이 내용을 `// TODO: 곡관 조합 해법 미정 (PROGRESS.md 참조)` 주석으로 남길 것.

### `Infrastructure/Repositories/Revit/Gis/RevitBendToleranceRepo.cs`

## 6. 신규 4·5·8·9 — 진단

### `Application/DTOs/Gis/PipeNetworkDiagnosisResult.cs`

```csharp
/// <param name="X">원본 GIS 좌표(m). Revit 내부좌표 변환은 배치 단계에서 한다.</param>
public sealed record PipeNetworkNodeReport(
    int NodeId, string Kind, int Degree, double X, double Y, double Z,
    double DeflectionDeg, double MaxDiameterMm, double MinDiameterMm,
    string PipeKind, string BendResolution, double StandardAngleDeg, double ResidualDeg);

public sealed record PipeNetworkDiagnosisResult(
    int NodeCount, int EdgeCount,
    IReadOnlyDictionary<string, int> KindCounts,     // NodeKind 이름 → 개수
    int BendStandardCount, int BendNoneCount,
    IReadOnlyList<PipeNetworkNodeReport> Attention,  // Unresolved + TooManyBranches + EndPoint
    IReadOnlyList<string> Warnings);
```

`Attention`은 사용자가 눈으로 확인해야 하는 절점만 담는다(정상 Tee/Cross/Straight는 집계에만 반영).
정렬 순서: `Unresolved` → `TooManyBranches` → `EndPoint`, 그 안에서는 `NodeId` 오름차순.

### `Application/UseCases/Gis/AnalyzePipeNetworkUseCase.cs`

- 주입: `IEnumerable<IAlignmentSourceReader>`, `IBendToleranceRepo`.
- **읽기 전용이므로 `ITransactionContext`를 주입받지 않는다.**
- 실행: 파일별 리더 선택(`PlaceAlignmentFamilyUseCase.Execute`의 리더 선택/`ApplyAttributes` 로직과 동일하게 처리)
  → `PipeNetworkBuilder.Build(alignments, snapToleranceMm / 1000d)`
  → `PipeNetworkClassifier.Classify` → `BendResolver.ResolveAll` → 집계.
- `IBendToleranceRepo.Load()`가 null이면 `BendToleranceTable.Default`를 쓰고
  `Warnings`에 `"허용굴곡 설정이 저장되지 않아 기본값으로 판정했습니다."`를 추가한다.

### UI — `PipeNetworkDiagnosisView`

`PipingView.xaml` / `AlignmentFamilyPlacementView.xaml`의 공통 스타일을 그대로 따른다. 탭 2개:

1. **진단** — 파일 목록(추가/제거, `IFileDialogService` 사용), 스냅 허용오차(mm, 기본 10),
   [진단 실행] 버튼, 요약 텍스트(절점/간선 수, 종류별 개수), `Attention` DataGrid(읽기 전용).
2. **허용굴곡 설정** — `BendToleranceEntry` 편집 그리드(행 추가/삭제), [저장] 버튼 → `SaveBendToleranceUseCase`.
   진입 시 `IBendToleranceRepo.Load()` 결과를, 없으면 `Default`를 채우고 "기본값(미저장)" 안내를 표시한다.

(`ServiceContainer.GetService<View>()` → `ShowDialog` → UseCase 실행 → `TaskDialog.Show`)로 작성한다.
리본 등록은 기존 관로 모델링 버튼이 등록된 자리 옆에 같은 방식으로 추가한다.
